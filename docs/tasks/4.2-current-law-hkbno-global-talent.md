# 任务 4.2：现行法律栏扩展——Hong Kong BN(O) 与 Global Talent（负责：Opus；Fable 验收）

## 目标

现行法律栏现在只建模 Skilled Worker（含其 dependant）与 Long Residence，其他路线的主申请人一律 `CL-SCOPE` 不通过、结论"信息不足"。本任务把 **Hong Kong BN(O)** 与 **Global Talent** 两条路线的主申请人纳入现行法律栏（用户决定先做这两条；家庭伴侣与难民留到下一波）。改革栏不变：HK BN(O) 仍按框架外短路，Global Talent 仍按核心许可 / 高人才分组评估。

## 工作方式

1. **第一个 commit 只做契约**：`packages/engine/src/types.ts` 的新增字段（如 Global Talent 的背书类型 / 背书机构；HK BN(O) 若 status holder 与 household member 合格期相同则不加字段）+ `docs/contracts.md` 新增 §12 "现行法律栏：HK BN(O) 与 Global Talent"（字段、参数名、规则与候选路径）。提交后**结束本轮回复**，列出契约改动与你拿不准的点；Fable 评审后用消息告诉你"继续"。评审通过前不要写规则。
2. 契约评审通过后 Fable 会把契约 commit 单独合到 main，astra 按它加问卷输入（4.6）；之后字段名与取值冻结。
3. **来源**：段落号以 sol 正在登记的 SRC-020（Appendix HK BN(O)）与 SRC-021（Appendix Global Talent）快照为准，4.1 合并前不要自己注册来源、不要引用未登记的 SRC。写契约时参数的 `sources` 可先写 `{ srcId: 'SRC-020', locator: '待 4.1' }` 占位；规则 commit 前 `git fetch origin main` 看 4.1 是否已合并：已合并 → `git merge origin/main` 后按快照填段号；未合并 → 结束回合说明"规则待 4.1"，Fable 合并后会让你继续。

## 规则（现行法律栏）

| 路线 | 要做的 | 来源 |
|---|---|---|
| Hong Kong BN(O) 主申请人 | `CL-SCOPE` 放宽；`CL-HKBNO-RESIDENCE-5Y`：连续 5 年持该路线许可（连续居留按 Appendix Continuous Residence，复用 `restartAfterAbsences`），不足时投影到期日；英语与 KOL 按该 Appendix（等级、2027-03-26 后是否升级，参数化）；status holder 与 household member 若同一合格期则不区分。候选 = 5 年 + `CL-ENGLISH` + `CL-KOL`。 | SRC-020 |
| Global Talent 主申请人 | `CL-SCOPE` 放宽；`CL-GT-RESIDENCE`：合格期 3 年或 5 年，取决于背书类型 / 机构（按快照的条款表参数化，契约字段表达用户申报的背书类型；缺省 → `UNKNOWN`）；英语与 KOL 按该 Appendix；候选 = 3 年或 5 年 + `CL-ENGLISH` + `CL-KOL`。此前在其他路线的时间是否可计入（如 Appendix 允许合并 Tier 1 Exceptional Talent 等），有条款就建模，没有就 `UNKNOWN` 登记 PD。 | SRC-021 |
| 共同 | `CL-ENGLISH` / `CL-KOL` 的解释写明按哪条 Appendix 的哪一段；Long Residence 10 年候选照常并列。dependant 不建模（仍"信息不足"，解释说明）。 | SRC-005、SRC-008 |
