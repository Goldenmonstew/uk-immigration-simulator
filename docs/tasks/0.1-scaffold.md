# 任务 0.1：仓库脚手架（负责：sol）

## 目标

把空仓库建成 pnpm monorepo：三个 package 空壳可以 build / test / lint / typecheck，CI 工作流就位。不写任何业务逻辑、规则或 UI。

## 背景（只需知道这些）

- 产品：UK Immigration Simulator，英国移民政策互动模拟器。核心是一个版本化规则引擎（`packages/engine`，纯 TypeScript，零框架依赖，浏览器可运行）、政策参数与 fixtures（`packages/policy-data`）、Web 应用（`apps/web`）。
- 设计依据：`docs/00-project-analysis-and-plan.md` §5 第 6 条、§6、§7。只需读 §5–§7。
- 工作约定：`AGENTS.md`（必读）。
- 工具链：Node 26、pnpm 10（已安装）。

## 要做的

1. 根目录
   - `package.json`：`private: true`，`packageManager` 写当前 pnpm 版本，`engines.node >= 22`；scripts：`build` / `test` / `lint` / `typecheck` / `format`（`pnpm -r` 即可，不强制 turbo）。
   - `pnpm-workspace.yaml`：`apps/*`、`packages/*`。
   - `tsconfig.base.json`：`strict: true`、ESM、`target: ES2022`。
   - ESLint flat config + typescript-eslint；Prettier；`.editorconfig`；`.nvmrc` 或 `.node-version`。
   - `README.md`（中文）：目录结构、常用命令、各 package 一句话职责。
2. `packages/engine`
   - `src/index.ts` 导出 `ENGINE_VERSION` 常量和一个占位函数即可。
   - vitest 一条测试。
   - 编译到 `dist`（tsc 或 tsup 二选一，简单优先）。
3. `packages/policy-data`
   - `src/index.ts` 占位导出；`schemas/` 与 `fixtures/` 目录各放一个 README 说明用途。
   - vitest 一条测试。
4. `apps/web`
   - Next.js 最新稳定版 + TypeScript + App Router，`output: 'export'` 静态导出。
   - 一个占位首页，引用 `packages/engine` 的 `ENGINE_VERSION` 并显示（证明 workspace 依赖打通）。
   - `pnpm --filter web build` 必须产出 `apps/web/out/index.html`。
5. `.github/workflows/ci.yml`：pnpm install（带缓存）→ lint → typecheck → test → build。
6. 确认 `.gitignore` 覆盖 `node_modules`、`dist`、`.next`、`out`、`coverage`、`.env*`、`.turbo`（`.worktrees/` 已有）。

## 不要做

- 不写规则逻辑、不写数据表、不写问卷 UI、不加 i18n、不加后端。
- 不引入 UI 库、状态库、数据库。
- 不改 `docs/`、`policy-sources/`、`PROGRESS.md`、`AGENTS.md`、`CLAUDE.md`。

## 验收命令（commit 前必须全部通过）

```bash
pnpm install
pnpm lint
pnpm typecheck
pnpm test
pnpm build
ls apps/web/out/index.html
```

## 提交

分 2–4 个 commit，例如：`Chore: 初始化 pnpm monorepo 与根配置`、`Chore: engine 与 policy-data 空壳`、`Chore: Next.js 静态导出壳`、`Chore: CI 工作流`。格式见 `AGENTS.md`。

按 `AGENTS.md` 的"完成时的报告"写最终消息，同样内容写入 `docs/tasks/reports/0.1-scaffold.md` 并提交。
