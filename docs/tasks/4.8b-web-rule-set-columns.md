# 任务 4.8b：版本化实现——web 部分（负责：astra；Fable 验收）

## 背景

4.8（Opus）为规则集版本化加了引擎与数据侧的机制：`RULE_SET_IDS` 单一入口、`RuleSet.effectiveFrom`（`status: 'IN_FORCE_FUTURE_VERSION'` 时必填）、`PARAMETERS: Record<RuleSetId, ParameterSet>`、`evaluate(request, registry?)`。现在 web 把 `RULE_SETS` 的全部值当作结果页的栏，`policyAsOf` 直接取 `earnedSettlement2026_11.asOf`。本任务按 `docs/contracts.md` §13.6 改 web：结果页永远只显示两栏、按状态选栏、徽章带生效日、/policy 列出全部规则集。现在只有两个规则集，所以页面输出应与现状一致；用测试里的合成第三规则集验证选择逻辑。

## 必读

- `AGENTS.md`；`docs/contracts.md` §13（尤其 13.5、13.6）；`docs/versioning.md` §5。
- `apps/web/lib/policy.ts`、`components/result-view.tsx`（两栏与徽章）、`components/policy-status.tsx`、`app/policy/page.tsx`、`app/about/about-content.tsx`（读 `ruleSets` 与 `policyAsOf` 的地方）、`lib/questionnaire.ts` / `lib/whatif.ts`（`evaluate` 调用是否传 `ruleSetIds`）、`i18n/{zh-CN,en}.ts` 的 `policy.*` 键；`packages/engine/test/versioning.test.ts`（Opus 的合成规则集写法，可复用到 web 测试）。

## 要做的

- `lib/policy.ts`：导出 `displayedRuleSets`（按 §13.6 选左右两栏：左 = `kind: 'LAW'` 且 `CURRENT_LAW`；右 = 有 `IN_FORCE_FUTURE_VERSION` 取 `effectiveFrom` 最早的，否则 `kind: 'ANNOUNCED'` 中 `RULE_SET_IDS` 里最靠后的）、`allRuleSets`（全部，按 `RULE_SET_IDS` 顺序）、`policyAsOf`（所显示两栏 `PARAMETERS[id].asOf` 的较晚者）。结果页、What-if、主申请人评估、本机情景摘要都只用 `displayedRuleSets`，并把 `ruleSetIds` 传给 `evaluate`（只评估这两栏）。
- 徽章：`IN_FORCE_FUTURE_VERSION` 用新键 `policy.IN_FORCE_FUTURE_VERSION.effectiveFrom`（中"已立法，{date} 起生效"，英"Laid, in force from {date}"），沿用现有插值写法；其他状态键不变。
- `/policy`：列出 `allRuleSets`（含未显示的），每条写状态、生效日（若有）、`asOf` 与来源；未显示的栏标一句"结果页未显示"。
- `/about` 的两栏说明读 `displayedRuleSets`。
- 测试：用合成第三规则集（`'current-law-test-future' as RuleSetId`，`IN_FORCE_FUTURE_VERSION`、`effectiveFrom: '2027-01-01'`）mock `RULE_SETS` / `PARAMETERS`，断言：两栏选择为 `current-law-2026-11` + 合成栏、徽章文案含日期、`policyAsOf` 为较晚者、/policy 列出三条；不 mock 时输出与现状一致（现有测试不变）。

- 不预先实现"旧规则集退役"或任何未在 §13.6 列出的逻辑。
