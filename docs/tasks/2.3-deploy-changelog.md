## A. 部署

现状：`apps/web` 是 Next.js 静态导出（`apps/web/out`），没有服务端特性；仓库目前没有 git remote，用户可能之后建 GitHub 仓库。两条路都要能用：本机直传，和远端就绪后的自动部署。

1. 根 `package.json` 加脚本 `deploy:pages`：`pnpm build` 后 `pnpm dlx wrangler@<精确版本> pages deploy apps/web/out --project-name "${CF_PAGES_PROJECT:?set CF_PAGES_PROJECT}"`。wrangler 版本用当前稳定版并写死（`npm view wrangler version` 查），不加依赖。账号 ID 与 token 走 wrangler 自己读取的环境变量 `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN`，仓库不存任何密钥。
2. `.github/workflows/deploy.yml`：push `main` 时跑一个 job——checkout、pnpm/action-setup@v6、setup-node@v7（`.nvmrc`、cache pnpm）、`pnpm install --frozen-lockfile`、`pnpm deploy:pages`；环境变量来自 `secrets.CLOUDFLARE_API_TOKEN`、`secrets.CLOUDFLARE_ACCOUNT_ID`、`vars.CF_PAGES_PROJECT`。不加 PR 预览、不加 concurrency、不加通知。
3. `docs/deploy.md`（中文，给用户看的操作步骤）：建 Pages 项目（Direct Upload，项目名建议 `uk-immigration-simulator`）；建 API token（Pages 编辑权限）与找 Account ID；本机首次部署的完整命令；`https://<项目名>.pages.dev` 预览；GitHub 远端就绪后在仓库设置里加两个 secrets 与一个 variable；绑定自定义域名的步骤（域名已在 Cloudflare，走 Pages 的 Custom domains）；上线前的 IAA 措辞复核提醒（见 phase-2-plan §4 第 2 条）。
4. 需要核实并写进 `docs/deploy.md` 的两点（查 Cloudflare 官方文档，写明文档 URL）：Pages 对 `/simulate` → `simulate.html` 的 clean URL 行为与尾斜杠处理；`_next/static` 的缓存是否需要 `apps/web/public/_headers`（不需要就不加，写一句结论即可）。
5. 不做：Workers、Functions、Access、analytics、`wrangler.toml`（Pages 直传不需要）。
