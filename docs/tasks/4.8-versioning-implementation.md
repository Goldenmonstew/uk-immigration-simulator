# 任务 4.8：规则集版本化实现——引擎部分（负责：Opus；Fable 验收；web 部分由 astra 另做）

## 目标

把 `docs/versioning.md` §4.1–§4.3 里需要代码支撑的部分做出来，让 Statement of Changes 落地时只需"加一个规则集 + 参数文件 + 规则差异"，不必再改框架。**不新增任何真实规则、参数或规则集**；用测试内的合成规则集证明机制。不过度工程化：每一项都要能被测试用到。

## 工作方式

- 契约先行：第一个 commit 只改 `packages/engine/src/types.ts`、`packages/policy-data/src/types.ts` 与 `docs/contracts.md` 新一节 §13"规则集版本化"，然后结束回合等 Fable 评审；评审通过后再实现。
- 一件事一个 commit，gate 全过再提交，不 push。astra 之后按 §13 做 web 部分（两栏选择、徽章、/policy 列表）。

## 必读

- `docs/versioning.md`（§1 现状、§4 新规则集、§5 web、§6 保留与退役）；`docs/contracts.md` §2、§7。
- `packages/engine/src/{evaluate.ts（RULE_SETS）,rule.ts（defineRule）,rules/index.ts（RULES）}`、`packages/policy-data/src/types.ts`（`RuleSetId`、`ParameterSet`）、`packages/policy-data/src/parameters/*.ts`、`apps/web/lib/policy.ts`（现在怎么用 `RULE_SETS`，astra 会改）。

## 要做的（契约里逐条定稿）

1. **`RuleSet` 加 `effectiveFrom?: IsoDate`**：`status: 'IN_FORCE_FUTURE_VERSION'` 时必填（已立法、未生效的生效日）；`CURRENT_LAW` / `ANNOUNCED_NOT_IN_FORCE` 不填。`evaluate` 不因它改变行为（哪两栏显示由 web 决定）。
2. **规则集注册可扩到三个**：`RuleSetId` 的来源改为一处（例如由 `RULE_SET_IDS` 常量推导），`RULE_SETS` / `RULES` / `PARAMETERS`（如新增）按同一键；加一个规则集 = 在这一处加一项。合成第三规则集（如 `current-law-test-future`）只在测试里注册——给出测试怎么注入而不进生产代码的办法（例如 `evaluate` 接受可选的 `registry` 参数，或 `RULES` 用可替换的模块级函数），选最简单且不影响现有调用的一种。
3. **同一规则挂到多个规则集**：`defineRule` 保持不变，加 `withRuleSet(rule, ruleSetId)` 之类的小函数，返回 `meta.ruleSetId` 不同、`check` 相同的规则；规则读取参数的方式不改（现在各规则直接 import 本版本参数）。**参数按规则集注入**（让同一 check 在不同版本下取不同参数）这一步在契约里讨论"现在做还是等真实版本出现再做"：我倾向等——没有第二个参数文件时无法测试它的正确性，且现有规则不必为此重写；你若认为现在做更省事，在契约里给出改法与范围，由 Fable 定。
4. **参数文件的"沿用"写法**：`ParameterSet` 加 `basedOn?: RuleSetId`（文档用途，表示值与来源沿用自哪个版本），`satisfies ParameterSet` 下仍能逐项覆盖；用 `docs/versioning.md` §4.2 的说明对齐。
5. **测试**：合成规则集 = 复用现行法律的全部规则（`withRuleSet`）+ `effectiveFrom: '2027-01-01'` + `status: 'IN_FORCE_FUTURE_VERSION'`；断言 `evaluate` 对三个规则集各出一栏且现有两栏的输出与快照不变、`fixtures` 的 `expected.ruleSetId` 仍只指向现有两个、`ruleSetIds` 过滤仍有效。bilingual 快照不应变化（合成规则集只在测试里）。
6. **文档**：`docs/contracts.md` §13（字段、注册方式、`withRuleSet`、测试注入方式、给 astra 的 web 契约：两栏选择规则——`CURRENT_LAW` + 有 `IN_FORCE_FUTURE_VERSION` 时显示它否则显示最新 `ANNOUNCED`；徽章文案键；`policyAsOf` 取所显示两栏 `asOf` 的较晚者；/policy 列出全部）；`docs/versioning.md` §4.3 与 §5 按实现微调。

## 不做

- 真实的 2027 规则集、参数或规则；web 改动；旧规则集退役逻辑；任何"将来可能需要"的额外接口。

## 验收（Fable）

- gate 全过；快照不变；合成规则集测试覆盖上面第 5 点；`RuleSetId` 的定义只在一处。
- 报告写入 `docs/tasks/reports/4.8-versioning-implementation.md`（四段）。
