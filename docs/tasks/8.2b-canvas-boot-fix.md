# 任务 8.2b：修复 Phaser 画布 0 宽度启动失败（负责：astra；Fable 验收）

## 现象（Fable 在 8.2 构建上用内置浏览器实测）

点"和林遥开始"后，覆盖层正常（属性、行动点、八个地点按钮都在），但地图区只有纯色背景：`canvas` 的属性尺寸是 0×360（宿主 `div.canvas` 的实际尺寸 949×655），控制台报 `Uncaught Error: Framebuffer status: Incomplete Attachment`（Phaser WebGL 渲染器在 `boot` 时创建帧缓冲失败），之后 `town.json` 与 `tileset.png` 从未被请求（只加载了 `characters/1.png`），场景没有 preload。原因：`new Phaser.Game({ width: element.clientWidth, height: element.clientHeight })` 在宿主刚挂载、尚未完成布局时拿到 0 宽度，0 宽画布让 WebGL 初始化崩溃，后续 `ResizeObserver` 的 `game.scale.resize` 救不回来。

## 要做的

- `apps/web/app/game/town-canvas.tsx`：等宿主有非零尺寸再创建 `Phaser.Game`（用 `ResizeObserver` 的第一次回调或 `requestAnimationFrame` 轮询到 `clientWidth > 0`），并改为 `scale: { mode: Phaser.Scale.RESIZE, width: '100%', height: '100%' }` 让 Phaser 自己按父元素取尺寸；`game.scale.resize` 只在宽高都 > 0 时调用。
- 若 WebGL 初始化仍失败（Phaser 抛错），回退 `type: Phaser.CANVAS` 重建一次，并在报告里说明。
- 本地复现：在 `pnpm --filter web build` 后用任意静态服务器打开 `/game`，确认画布尺寸随宿主、地图与角色可见；若你的环境没有浏览器，至少写一个用 jsdom + ResizeObserver mock 的单元测试证明"宿主 0 宽时不创建 Game、非零后才创建"（把创建 Game 的调用抽成可注入的工厂）。
- 不改其他文件；不改 mock 核心与覆盖层。

## 验收（Fable）

- 构建后浏览器里 `canvas` 尺寸与宿主一致，地图与角色可见，`town.json` / `tileset.png` 请求 200，控制台无错误；键盘与点按行走正常。
