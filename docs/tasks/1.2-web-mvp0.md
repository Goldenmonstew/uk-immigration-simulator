# 任务 1.2：问卷流与结果页（负责：astra；Fable 验收）

## 目标

在 `apps/web` 实现 MVP-0 的三个页面：首页（定位与免责说明）、问卷（分步收集 `PersonTimeline`）、结果页（两栏：现行法律 / 已公布改革），直接调用 `packages/engine` 的 `evaluate()`。引擎规则由 Opus 并行实现：你先对着契约和 stub 开发，用本地 mock 结果调试结果页。

## 必读

- `AGENTS.md`（尤其"不要过度工程化"）。
- `docs/contracts.md`：契约唯一真相是 `packages/engine/src/types.ts` 与 `packages/policy-data/src/{types,routes}.ts`。
- `docs/00-project-analysis-and-plan.md` §2、§5 第 1 / 4 / 5 / 11 / 12 / 13 条（产品语言与隐私）、§10（Cloudflare Pages 静态部署）。

## 页面与流程

1. `/`：产品一句话定位（语气见 plan §5 第 12 条：展示可能适用的路径、关键条件与未定事项，不是决定你能不能移民）；政策状态标注（`policyAsOf`，两个规则集的 `status` 文案：现行法律 / 已公布、未生效）；"开始模拟"按钮；免责说明（plan §5 第 12 条的英文段落加中文）。
2. `/simulate`：分步问卷，每步一组问题，GOV.UK 风格（单列、大标签、明确的"继续 / 返回"、错误提示贴着字段）。顺序：
   - a. 基本信息：出生日期、国籍（ISO 3166-1 alpha-3，输入框加常见国家建议即可）。
   - b. 高风险筛查（尽早）：有无犯罪记录（英国或海外）、有无移民违规（逾期、违反条件、欺骗、妨碍管制、非法入境）、是否有未清偿政府债务、是否曾寻求庇护或走人权类路线。任一"是" → 直接进结果页：显示 `shortCircuit.message`（stub 阶段用你自己的占位文案）并建议寻求受监管建议，不再收集后续信息。
   - c. 签证历史：可增删的 episode 列表（`route` 从 `Route` 枚举选，显示中文名 + 英文原名；`validFrom` / `validTo`；`role`；SKILLED_WORKER 时显示 `socCode`、`salary` 两个可选输入）。
   - d. 缺席：可增删的区间列表，可跳过。
   - e. 收入：按 tax year 的年收入表（默认列出模拟日期之前的 7 个 tax year；留空 = 未知；可填 `partnerEarnings`）。
   - f. 福利：可增删，`benefitType` 下拉。Opus 并行在 `packages/policy-data/src/data/` 写 public funds 表（大写蛇形英文名，如 `UNIVERSAL_CREDIT`）；你先用本地占位常量，合并后换成 policy-data 导出。
   - g. 家庭关系：伴侣 / 父母 / 子女与对方身份（British citizen / settled / other）。
   - h. 英语与 Life in the UK：CEFR 等级或豁免；Life in the UK 通过 / 豁免 / 未填。
   - i. 模拟日期（默认今天，可改）。
   最后一步"查看结果"调用 `evaluate()`。
3. `/result`：
   - 顶部：`policyAsOf` 与两个规则集的 `status` 标签（来自 engine 导出的 `RULE_SETS`）。
   - 有 `shortCircuit` 时只显示其 message 与"寻求受监管建议"提示。
   - 两栏，每栏：`outcome` 的中文标签与解释（六态文案见 `contracts.md` §2）、`pathwayYears`、`earliestDate`、"为什么"（`rules[]` 按 `status` 分三组：未满足 / 未知 / 已满足，每条显示 `title`、`explanation`、来源，来源先显示为文本 `SRC-001 p16` 并链接到 `docs/SOURCES.md` 中对应的 URL；URL 表可以从 `docs/SOURCES.md` 手工摘到 `apps/web/lib/sources.ts`，只摘 SRC-001 到 SRC-016 的 URL）、假设清单。
   - "修改输入"返回问卷并保留已填内容。
   - stub 阶段 `evaluate` 对所有规则集返回 `INSUFFICIENT_INFORMATION` 且 `rules` 为空：结果页要能正常显示这个状态。另写 `apps/web/lib/mock-results.ts` 放两份手写的 `SimulationResult`（一份 `LIKELY_ELIGIBLE` 带几条 PASS 规则，一份 `LIKELY_NOT_ELIGIBLE` 带 FAIL 与 UNKNOWN）用于开发预览，通过 URL 参数 `?mock=1` / `?mock=2` 启用，页面上不放入口。

## 状态与数据

- 问卷状态用 React `useReducer` 放在 `/simulate` 页面层；草稿存 `localStorage`（刷新不丢，试读写要 try/catch 一次即可）；不引入状态库、表单库。
- 不发任何携带用户输入的网络请求；没有后端。
- i18n：自写 `t(key)` 与两份字典 `apps/web/i18n/zh-CN.ts`、`apps/web/i18n/en.ts`（en 先只填首页与结果页标签即可），默认 zh-CN，不引入 i18n 库；`Route` 枚举的中文名表也放 `apps/web/i18n/` 下。引擎返回的 `title` / `explanation` / `assumptions` 本身就是中文，直接显示。

## 技术约束

- Next.js App Router，保持 `output: 'export'`，所有页面可静态导出；交互用 `'use client'` 组件。
- 样式用 CSS Modules（零依赖）；不引入 UI 组件库、Tailwind、图标库、日期库。
- 移动端可用：单列布局、触控尺寸、375px 宽不横向溢出。
- 不改 `packages/**`、`docs/**`、根配置；不 push。需要契约字段而没有的，写进报告，不自己加。
