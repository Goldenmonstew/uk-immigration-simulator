## 改动清单

1. **web 显式依赖 policy-data。** `apps/web/package.json` 加 `"@uk-immigration/policy-data": "workspace:*"`，`next.config.ts` 的 `transpilePackages` 加上它，`lib/policy.ts` 与 `lib/mock-results.ts` 的 `../../../packages/policy-data/src` 相对导入改为包名导入。允许改锁文件（`pnpm install`）。
2. **福利下拉换成数据表。** 删除 `lib/benefits.ts`；问卷福利步骤的下拉改用 `publicFundsBenefits.publicFunds` 与 `publicFundsBenefits.notPublicFunds`（两组，`<optgroup>` 即可，组名用 i18n 键），`benefitType` 为值、`name` 为显示文字。新增记录的默认值继续用 `UNIVERSAL_CREDIT`。
3. **政府债务交给引擎。** 筛查步骤的"是否有未清偿的政府债务"不再短路：回答"是"时继续问卷，`runSimulation` 把 `governmentDebt` 设为 `{ outstanding: draft.screening.debt === 'yes' }`，由 `ES-DEBT` 规则给出 FAIL。犯罪记录 / 移民违规 / 庇护三项仍由前端合成短路（契约的 `CriminalEvent` / `ImmigrationBreach` 需要日期，庇护经历没有字段；Phase 2 再补），`reasons` 映射去掉 `debt`。筛查步骤的提示文案相应调整（只有前三项会直接进结果页）。对应测试改掉 `test.each(screeningKeys)` 里对 debt 的断言：debt = yes 应得到正常 `byRuleSet`，且 Earned Settlement 栏的 `ES-DEBT` 为 `FAIL`。
4. **结果页展示引擎的短路。** 现在 `result.shortCircuit` 一出现就只显示 message、不渲染两栏；但引擎返回的 `PROTECTION` / `OUTSIDE_FRAMEWORK` 短路带着完整的 `byRuleSet`（现行法律一栏照常评估，Earned Settlement 一栏是 `REQUIRES_REGULATED_REVIEW` 并保留 `rules`）。改为：`byRuleSet` 为空（前端合成）时维持现状；非空时把 `shortCircuit.message` 作为页首提示（`site.notice` + `site.warning`）显示，两栏照常渲染。
5. **结果页新增三处展示。**
   - `assessment.routeGroup` 有值时在"路径所需年限"旁加一行"路线分组"，中文标签放 `apps/web/i18n/routes.ts`（7 个 `RouteGroup` 值，格式同 `routeNames`：中文 · 英文原名）。
   - 规则条目：`rule.pendingDetails` 非空时在来源后面加一个小标签"政府未定细节：PD-012、PD-013"（纯文本，不链接；样式用现有 `site.badge` 或一个新 class 即可）。
   - 假设清单：用原生 `<details>` 折叠，`<summary>` 显示"假设清单（N 条）"，默认收起；没有假设时维持现有文案。
6. **`mock-results.ts`** 的手写结果补上 `routeGroup` 与一条带 `pendingDetails` 的规则，让 `?mock=1` 能预览第 5 条的展示。
