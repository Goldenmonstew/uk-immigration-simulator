# 任务 3.5：难民路径的问卷与结果页（负责：astra；Fable 验收）

## 背景

3.4（Opus）让引擎对三条保护类路线（`SAFE_AND_LEGAL`、`CORE_PROTECTION`、`PROTECTION_WORK_AND_STUDY`）给出真实结论，并把"成年后非法入境"在保护类路线上改为"年限 +10"而不是短路。契约字段已合到 main，见 `docs/contracts.md` §11（**字段名与取值以它为准**，本任务书的字段名只是摘要）：

- `ImmigrationEpisode.resettlementScheme?: 'UK_RESETTLEMENT_SCHEME' | 'OTHER_DESIGNATED'`（仅 `SAFE_AND_LEGAL`）
- `ImmigrationEpisode.sustainedActivity?: 'WORK' | 'EDUCATION' | 'TRAINING'`（仅 `PROTECTION_WORK_AND_STUDY`）
- `ImmigrationBreach.article31?: boolean`（仅 `ILLEGAL_ENTRY`）
- `PersonTimeline.asylumSupportRepayment?: 'NOT_REQUIRED' | 'REPAID' | 'ON_PLAN' | 'OUTSTANDING'`

现在的问卷有两处挡在引擎前面：筛查步骤的"是否曾寻求庇护或走人权类路线"与"是否有移民违规经历"回答"是"都直接短路（`shortCircuitKeys`），引擎根本收不到 `immigrationBreaches`。本任务把这两处交给引擎决定。

## 必读

- `AGENTS.md`；`docs/tasks/phase-3-plan.md` §2 的 3.5；`docs/contracts.md` §11。
- `apps/web/lib/questionnaire.ts`（`steps`、`shortCircuitKeys`、`Screening`、`runSimulation`、`validateStep`）、`app/simulate/page.tsx`（筛查步骤约 L350；签证片段的路线专属字段约 L395–L560，Skilled Worker 的 SOC / 薪资 / ISL 字段是样板）、`lib/share.ts`（`validTimeline`）、`components/result-view.tsx`、`i18n/{zh-CN,en}.ts`。
- `packages/policy-data`：`ROUTE_GROUPS`（判断某路线是否属 `PROTECTION`）、`display-names.ts` 的 `breachTypeNames`（违规类型的中英文名，直接复用，不要在 web 再抄一份）。

## A. 筛查步骤

- 去掉"是否曾寻求庇护或走人权类路线"这一问（保护类路线由签证片段的路线选择表达）。旧草稿里残留的 `screening.protection` 键照常读入、忽略即可，`Draft.version` 仍为 1。
- "是否有移民违规经历"回答"是"时**不再短路**，改为在同一步展开一个可增删的"违规记录"列表，每条：类型（下拉，选项与文字来自 `breachTypeNames`）、发生日期（日期字段，必填）、当类型为非法入境时追加一问"是否认为自己受 Refugee Convention Article 31 保护"（不确定 / 是 / 否 → `article31` 缺省 / true / false）。写入 `timeline.immigrationBreaches`；回答"否"时清空。犯罪记录一问维持短路。主申请人子流程同样处理。
- 更新 `screening.hint` / `screening.message` 等文案（中英）：现在只有犯罪记录会停止问卷；移民违规由规则引擎评估（非保护类路线上的成年后非法入境仍会由引擎给出"需要受监管建议"）。

## B. 签证片段的路线专属字段

- 路线为 `SAFE_AND_LEGAL`：下拉"安置 / 担保路线"——UK Resettlement Scheme / 其他指定的安置或担保路线 / 不确定（→ `resettlementScheme` 两个取值 / 缺省）。
- 路线为 `PROTECTION_WORK_AND_STUDY`：下拉"在该路线上的持续活动"——工作 / 教育 / 培训 / 不确定（→ `sustainedActivity`）。
- 切换路线时清掉这两个字段（与 `socCode` 等同样处理）。`CORE_PROTECTION` 无专属字段。

## C. asylum support 偿还

- 在"福利与法定支付"步骤末尾加一问，仅当任一签证片段的路线属 `PROTECTION` 分组时显示："是否需要偿还 asylum support 费用"——不需要偿还 / 已全额偿还 / 按还款计划偿还中 / 有未偿还 / 不确定（→ `asylumSupportRepayment` 四个取值 / 缺省）。

## D. 结果页

- 当模拟日当天有效的片段属 `PROTECTION` 分组时，在两栏上方加一条提示（中英）："保护类路线的结论只反映已公布的政策框架；Article 31 保障、路线推出前已有时间是否计入、偿还与 public funds 细则等尚未公布，请连同待定事项阅读。"现有"寻求受监管建议"区块保留。
- 短路页（`result.shortCircuit`）不变。

## E. 其他

- `lib/share.ts` 的 `validTimeline`：新字段是可选字段，分享链接里带或不带都要能通过；What-if 与本机情景不改。
- 核对 `/policy` 页会自动列出 3.4 的新规则（页面读引擎规则表；若有手写清单则补）。
- 测试：违规记录（含 Article 31）进入引擎请求；回答"否"清空；保护类字段与 `asylumSupportRepayment` 进入请求；breach 不再在 web 层短路；带 `screening.protection: 'yes'` 的旧草稿能载入且不短路；`decodeDraft` 接受带新字段的草稿。
