# 任务 2.9：引擎双语解释（负责：Opus；Fable 验收）

## 目标

英文界面（2.8）已经上线，但规则的 `title` / `explanation` / `assumptions`、`shortCircuit.message` 和聚合层的假设都是引擎里写死的中文。本任务让引擎按请求的语言产出这些文案，web 之后（2.10）删掉它手写的英文映射 `apps/web/i18n/policy.ts`。不改任何规则语义。

## 工作方式（同 2.2 / 2.5）

1. **第一个 commit 只做契约**：`SimulationRequest.locale?: 'zh-CN' | 'en'`（缺省 zh-CN）；`RuleMeta.titleEn?: string`（新增可选字段，所有规则都填，用测试保证齐全；`title` 仍是中文、不改）；`docs/contracts.md` §10 写清数据流与约束。提交后结束本轮回复，列出改动与你拿不准的点；Fable 评审后再动文案。
2. 之后一条规则文件一个 commit（`es-requirements.ts`、`es-residence.ts`、`es-contribution.ts`、`es-transitional.ts`、`es-dependant.ts`、`current-law.ts`、`evaluate.ts` 短路、`aggregate.ts` 假设与投影说明）。gate 全过后自己 commit（`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`），不 push。
3. 不碰 `apps/web/**`。policy-data 里只改 `src/data/policy-changelog.ts`（加 `titleEn` / `summaryEn`，可选字段，五条都填）与 `src/index.ts`（如需）。

## 必读

- `AGENTS.md`（不过度工程化：不引入 i18n 库、不做消息目录、不做占位符模板系统）。
- `docs/contracts.md` §2、§3；`apps/web/i18n/policy.ts`（astra 手写的英文规则标题与变更日志译文，可直接采用其措辞，合并后由 2.10 删除）；`apps/web/i18n/en.ts` 的用词风格（GOV.UK 式短句，法律术语原文）。

## 实现约束

- 机制保持最直接：每次评估从 `ctx.locale` 得到一个选择函数（例如 `const L = (zh: string, en: string) => ctx.locale === 'en' ? en : zh`），中英文字符串并排写在同一处，便于对照与维护；数字、日期、金额照常从参数插值。
- `RuleOutcome.title` 在 `runRule` 里按 locale 取 `meta.title` 或 `meta.titleEn`；`SettlementAssessment.assumptions` 去重逻辑不变。
- 英文文案规则：法律术语保留原文（Skilled Worker、public funds、settlement、Life in the UK），引用用原文段号（SW 24.3、p29），金额 `£50,271`，日期 ISO。不要音译中文说法。
- 现有中文测试断言不动；新增一条通用测试：对全部 fixtures 与 `RULES` 的样例上下文以 `locale: 'en'` 评估，断言所有 `title` / `explanation` / `assumptions` / `shortCircuit.message` 非空且不含 CJK 字符；另一条断言每条规则 `meta.titleEn` 非空。
- fixtures 与现有结论不变（默认 zh-CN）。

## 验收（Fable）

- 报告写入 `docs/tasks/reports/2.9-engine-bilingual.md`（四段）。
