## A. 路线与分组名复用 policy-data

- 删除 `apps/web/i18n/routes.ts` 里自己维护的路线与分组名，改为直接用 policy-data 导出的 `routeNames` / `routeGroupNames`（`{ 'zh-CN', en }` 形状相同）；中文模式继续显示"中文 · English"（若 policy-data 的中文名不带英文后缀，则在 web 拼接 ` · ${en}`），英文模式只显示英文，分组英文大小写以 policy-data 为准（sentence case）。更新引用与测试（`test/locale.test.tsx` 等）。

## B. 英文界面的标点

- 组件里硬编码的全角标点（如 saved-scenarios 的 `：`、result-view 的 `（n）`、`：`、`、`）按语言选择：中文用全角，英文用半角 `: `、` (n)`、`, `。做法用一个小的 i18n 辅助（如 `punct(locale)` 返回常用标点）或把这些标点放进 i18n key，二选一，不要两套。

## C. /about 方法说明页（中英）

- 新页面 `app/about/page.tsx`（静态元数据 + 客户端内容的拆法同首页 / 结果页），导航栏加入口（`site-shell.tsx`），`public/sw.js` 预缓存清单加 `/about` 并把缓存版本号递增。
- 内容（文案用 i18n key，中英各一份）：
  1. 这是什么：按已公布政策推算定居路径的参考与理解工具，带一点游戏性；不判定法律身份，不替代受监管建议。
  2. 两栏的含义：现行法律（Immigration Rules 当前版本）与已公布改革（Earned Settlement，已公布、未生效），各自覆盖哪些路线、哪些仍为"信息不足"（现行法律栏现在只建模 Skilled Worker 与 Long Residence，4.2 合并后由 Fable 更新这一句——留一个 i18n key）。
  3. 数据来源与政策核对日期：读 `lib/policy.ts` 的 `policyAsOf` 与规则集信息（与 /policy 页同一数据源），链接到 /policy。
  4. 未定事项：说明"待定事项（PD-xxx）"在结果页的含义，链接到 /policy 的相应区块或来源。
  5. 隐私：输入只存本机（localStorage）、分享链接含全部输入、站点只用 Cloudflare Web Analytics（无 cookie）。
  6. 不提供反馈入口（用户决定）。
- 结果页与首页的免责说明里加一个指向 /about 的链接。

## D. a11y 自查与修正

- 沙箱里没有浏览器，按清单人工核对并修：每个表单控件有 `<label>`；标题层级不跳级；`role="status"` / `aria-live` 用在复制、保存等即时反馈上；焦点可见（`:focus-visible` 样式）；颜色对比度按现有 CSS 变量算一遍（正文 ≥ 4.5:1，大字 ≥ 3:1）；跳转链接（skip link）可用；表格有 `scope` / `data-label`（已有，核对）。只修真实问题，不加框架。Fable 验收时会在本机跑 Lighthouse 的 accessibility 类别。

## E. 复查
