分支 `claude/rules-4-5-4-8-0e36a1`。契约 `e0385b2` 已由 Fable 评审通过。实现按 contracts §13.2–13.7 完成，没有新增真实规则集、参数或规则，web 部分没有改动。

## 1. 做了什么（按 commit）

- `e0385b2` Docs：契约。
  - `RULE_SET_IDS` 为唯一入口，`RuleSetId` 由它推导；`ParameterSet.basedOn?`。
  - `RuleSet` 改为按 `status` 区分的联合类型（`IN_FORCE_FUTURE_VERSION` 时 `effectiveFrom` 必填，其余状态不能填）；新增 `RuleSetRegistry`。
  - contracts §13。
- `52dafc3` Feat：`PARAMETERS: Record<RuleSetId, ParameterSet>`（`packages/policy-data/src/parameters/index.ts`）；`policy-data` 的 `index.ts` 导出 `RULE_SET_IDS` 与 `PARAMETERS`。新增 `engine/test/versioning.test.ts`，覆盖三张表的键一致性和 `basedOn` 写法。

  - 测试里加了合成第三规则集。
- `a0b2440` Docs：`docs/versioning.md` 的 §1、§4.1–4.3、§5 按实现微调，并写明"参数按规则集注入尚未实现：数字有变化的规则要另写"。

## 2. 怎么验证的

- 每个 commit 前跑 `pnpm lint && pnpm typecheck && pnpm test && pnpm build`，退出码均为 0。改动文件已过 prettier。
- `packages/engine/test/versioning.test.ts`（27 个用例），对应任务书的五项：
  1. **`effectiveFrom`**：两处 `@ts-expect-error` 锁定类型——`IN_FORCE_FUTURE_VERSION` 缺 `effectiveFrom`、`CURRENT_LAW` 带 `effectiveFrom`，都必须是类型错误。typecheck 覆盖了 `test/`，如果某处不再报错，`tsc` 会因为多余的 `@ts-expect-error` 而失败。
  2. **注册**：`RULE_SETS`、`RULES`、`PARAMETERS` 的键都等于 `RULE_SET_IDS`，并且 `RULE_SETS[id].id`、`PARAMETERS[id].ruleSetId`、`RULES[id]` 里每条规则的 `meta.ruleSetId` 都等于 `id`。合成规则集通过 `evaluate(request, registry)` 注入，没有进入生产代码。
  3. **`withRuleSet`**：现行法律的全部规则经 `withRuleSet` 后，`meta` 只有 `ruleSetId` 不同，原规则不变；在 17 个样例上下文上的运行结果相同。
  4. **`basedOn`**：在 `satisfies ParameterSet` 下展开沿用、覆盖一项，沿用的值与覆盖的值、来源都正确。
  5. **合成规则集** `current-law-test-future`（`withRuleSet` 复用现行法律全部规则，`IN_FORCE_FUTURE_VERSION`，`effectiveFrom: '2027-01-01'`）：
     - 21 个 fixture 各出三栏，键顺序为 `[...RULE_SET_IDS, 合成 ID]`；
     - 去掉合成栏后，整个结果（含 `policyAsOf`、`shortCircuit`）与不传 registry 时 `JSON.stringify` 逐字节相同；
     - 合成栏与 `current-law-2026-11` 栏相同，包括 HK BN(O) 的 `OUTSIDE_FRAMEWORK` 短路：合成栏 `kind: 'LAW'`，不被停；
     - `ruleSetIds: [合成 ID]` 只出合成栏，`['earned-settlement-2026-11']` 只出该栏；
     - 所有 fixture 的 `expected.ruleSetId` 都在 `RULE_SET_IDS` 里，且不是合成 ID。
- `bilingual` 快照没有更新，原样通过（没有用 `-u`）。

## 3. 没做或没验证的

- web 部分（§13.6：两栏选择、徽章键、`policyAsOf`、/policy）由 astra 另做；`apps/web` 没有改动。

## 4. 发现与建议（范围外，未实现）

- `RuleSet.effectiveTo` 与 `supersedes` 仍未被任何代码使用。退役流程（`docs/versioning.md` §6）落地时再决定保留还是删除。
- `SimulationResult.policyAsOf` 仍固定为 `earnedSettlement2026_11.asOf`。web 改用 §13.6 的算法后，这个字段只有快照在用；以后可以改成"所评估规则集 `asOf` 的较晚者"，但会改快照，所以这次没动。
- contracts §2 说 `POLICY_NOT_YET_IN_FORCE` 用于"规则集有已知 `effectiveFrom` 且晚于模拟日"，但按 §13 的约定，`evaluate` 不读 `effectiveFrom`，引擎目前也不会输出这个结论。真实的 `IN_FORCE_FUTURE_VERSION` 规则集出现时，需要在它的契约里定下：模拟日早于生效日时，是照常评估（现在的行为），还是输出 `POLICY_NOT_YET_IN_FORCE`。
