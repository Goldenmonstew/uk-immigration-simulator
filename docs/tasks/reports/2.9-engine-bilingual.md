## 2. 怎么验证的

- `pnpm lint && pnpm typecheck && pnpm test && pnpm build`：退出码 0。测试数：engine 264（原 200，新增 14 个快照测试与 50 个英文测试），policy-data 16，web 69。`prettier --check` 通过。
- **中文逐字不变**：
  - 快照在 `498aed5` 记录，之后每个 commit 都跑一遍，快照文件始终未改动。
  - 另用一次性脚本（放 scratchpad，不提交）以 TypeScript AST 对比 8 个源文件：把 `5a66415` 与当前版本中所有含中文的字符串 / 模板字面量取静态部分，逐文件比较多重集合，8 个文件全部相同（合计 229 条）。
  - 同一脚本还检查了所有中文字面量的位置，都在 `L(...)` 的第一个参数、`title` 或 `earningsRule` 的中文标题参数中。唯一例外是 `evaluate.ts` 的 `textFor(ctx)(zh, en)` 直接调用，属正常写法。
- **英文抽读**：临时测试打印 p31 A、p45 A 与 "Skilled Worker 2019-11-01 起、£55,000、SOC 2136、有一次缺席" 三个场景的 `locale: 'en'` 全部输出，跑完删除。逐条读过：

  - 结论、年限、日期与默认 locale 相同。

- 没碰 `apps/web/**`：web 仍用手写的 `englishRuleTitles` / `englishPolicyChanges`，调用 `evaluate` 时不带 locale（留给 2.10）。
- 英文测试只能证明"非空、无 CJK"，不能证明译文准确。准确性只靠上面三个场景的人工抽读；fixtures 与样例没覆盖到的英文分支（如 SW 39.1(b)、going rate 附加表不符）只做过代码层面的对照。

## 4. 发现与建议（范围外，不实现）

- `policy-changelog.ts` 中 HC 584 一条的 `locator: '版本 2026-10-08'` 仍是中文，英文政策页显示来源时会露出中文。
