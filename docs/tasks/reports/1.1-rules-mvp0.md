## 4. 发现与建议（范围外，未实现）

1. **fixture 冲突（C、D）**：两个 fixture 早于 `PersonTimeline.lifeInTheUk`（`ce52d49`），没有这个字段，按契约"缺省 = 用户没提供"，`ES-KOL` 为 UNKNOWN，C 原样得到 `INSUFFICIENT_INFORMATION`（期望 `LIKELY_ELIGIBLE`）；D 原样仍为 `LIKELY_NOT_ELIGIBLE`。未改 fixture。`evaluate.test.ts` 对这两个 id 在缺字段时补 `lifeInTheUk: { passed: true }` 后断言，另有一个测试记录原样结果。建议 Fable 给 C / D 补上该字段，然后删掉测试里的 `PRE_KOL_FIXTURES`。
2. **CL-ENGLISH 与 brief 不同**：brief 写"申请日 < 2027-03-26 → B1"。快照原文中 Skilled Worker 主申请人的定居规则只有 SW 22A.1（2027-03-26 起 B2），此前没有定居英语要求（B1 在 dependant 的 SW 44.1 与 LR 13.1(a)）。按原文实现：SW 主申请人此前 PASS，LR 此前 B1。若按 brief 实现，英语未填的 SW 申请人会被判 `INSUFFICIENT_INFORMATION`。
3. **PD-041 的"对引擎的影响"与已定口径不一致**：登记表写"7 年中达标 ≥3 且 <5 年时输出 UNKNOWN"，brief 已定口径为按 Table 1、声明假设。按 brief 实现（FAIL + 假设），建议更新 PD-041 该栏。PD-007（历史年份按当年门槛）同理：参数只有现行一套门槛，实现为"统一按现行门槛"并声明。
4. **Annex C 的 SOC 代码**：Annex C 只有职业名，代码按同名职业取自 SRC-004 SW 16.1（"Registered … nurses" 在 SW 16.1 中不带 Registered）。若要更直接的来源，可登记 Appendix Skilled Occupations Table 3。
5. **sol 的 lint**：`dates.ts` 的 `MS_PER_DAY = 86_400_000` 用了 `eslint-disable-next-line no-restricted-syntax`；lint 规则合并前这个注释是"未使用"，ESLint 只给 warning。
6. **给 astra**：`benefitType` 取值以 `publicFundsBenefits` 为准（命名约定见 `contracts.md` §4）；`routeGroup` 取路线的第一个分组（Skilled Worker 显示 `CORE_PERMISSION`）；现行法律栏在路线不在建模范围时 `rules` 只有 `CL-SCOPE` 一条。
7. **产品层**：强制要求 FAIL（如英语 B1）时不给预计日期，即使用户可以补足；现行法律下非 Skilled Worker、未满 10 年的人只得到 CL-SCOPE 的 UNKNOWN，没有 LR 推算日期（brief 口径）。两者都可以考虑在后续版本给"补足后"的推算。
8. `ES-PUBLIC-FUNDS` 未处理"在 no recourse to public funds 条件下领取即属 breach"的情形；asylum support 等不在 SRC-006 两张表里的福利一律 UNKNOWN（PD-013）。
