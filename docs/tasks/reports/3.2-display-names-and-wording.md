## 4. 发现与建议（范围外，不实现）

- ISL 条目都带 `removalDate`（多数 "31 December 2026"，6135 / 6136 为 "22 July 2028"）。推导不看这个日期，模拟日期或投影日期晚于移除日时，仍会按在清单上处理。建议后续由 sol 把 `removalDate` 规范成 ISO 日期，再由 Opus 在推导时比较申请日。
- SOC 6135 / 6136（care worker）推导为在清单上后，满足 SW 4.2(b) 的 care worker 在现行法律栏会降到 row D（£25,000），见 commit 8。这是 brief 要求的口径，但实际上 6135 能否担保受 SW 6.1B 限制；Fable 验收时可确认这一结果可以接受，或要求 care worker 职业不做推导。
- 中文"且${原因}"在原因以 SOC 开头时会写成"且SOC 6135 属…"（缺空格），是 2.5 起就有的拼接问题，本次 fixture 里出现了；小修，可留到下次文案通读。
- 中文其他句子里大量保留英文路线名（"Skilled Worker 许可"、"dependent partner"），这是 2.9 前就有的法律术语写法，本任务只替换了枚举码。若希望中文统一用"技术工作者"等，需要另定规则（哪些术语保留原文）。
- 分组英文名大小写、web 复用显示名两条已由 Fable 记下，留给 astra 的后续任务。
