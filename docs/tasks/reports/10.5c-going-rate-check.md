## 结论

- **O1：换行正确，换行日期也正确。**
  - 现行规则下，SW 24.3 row C 适用的前提是申请日早于 2030-04-04。林遥按 row C 定居的窗口是 2029-01-15（满 5 年）到 2030-04-03。
  - 2030-07-15 评估时已过截止日，只能落到 row A：£41,700，going rate 查 Table 1，SOC 2134 为 £54,700。年薪 £49,920 不够，`FAIL` 是对的。
  - SRC-001 p44 宣布这一群体"可按现有条件续签至 2035"。这条还没写进 Rules，现行法律栏不应采用（PD-040 已登记）。
- **O2：不改变任何规则结论。**
  - "工资面谈"把整段许可的 salary 改写，起点仍是 2024-01-15。引擎只读评估日所在许可段的 salary，不读过去某天的薪资。
  - 收入年份只读 `incomeYears`，不从许可段推导。
  - 引擎不判断续签。
  - 因此，为了引擎结论正确，游戏不必把这一段拆开。

### O2："工资面谈"整段改写 salary

**引擎读 salary 的位置**：`ImmigrationEpisode.salary` 只在三处被读到，都经 `episodeOn(timeline, simulationDate)` 取评估日所在的那一段。

- `CL-SW-SALARY`：`current-law.ts:1879`。
- `CL-SW-GOING-RATE`：`current-law.ts:1971`。
- `ES-TRANSITIONAL-CARE-WORKER`：`packages/engine/src/rules/es-transitional.ts:38`、`:80–104`，只对 SOC 6135 / 6136。

没有规则读更早日期的薪资或薪资历史。这与条文一致：SW 24.2 要求 sponsor 确认申请人现在以及可预见的将来，薪资不低于 SW 24.3。

**逐项结论**：

- **定居薪资判断**：只看评估日的薪资，过去那部分改成什么都读不到。
  - 选行不看薪资：`settlementSalaryRow` 只用 SOC、ISL 申报、连续 Skilled Worker 段起点和申请日。
  - 改写不动 `validFrom` / `validTo`，所以行、居留年限、连续性都不变。
- **续签**：引擎没有 Skilled Worker 续签规则，只判断定居。
  - 游戏的 `extend` 行动（`packages/game/src/game.ts:645`）把当前段连同新 salary 复制成下一段，不经引擎核对。
  - 所以不存在可被改变的引擎续签结论。
- **收入年份**：引擎只读 `timeline.incomeYears`，不从许可段的 salary 推导。读它的规则：
  - `current-law.ts:1120`（Appendix FM）；
  - `es-contribution.ts:45–56`；
  - `es-protection.ts:298`。

  游戏的 `syncSalary`（`game.ts:366`）只做两件事：
  - 把新薪资写进 `validTo ≥ 今天` 的许可段；
  - 写进当前 tax year 的 `incomeYears`。

  过去的 tax year 不动。所以整段改写的"过去部分"到不了收入年份。

**复现**：比较完整的 `evaluate` 输出（两栏、全部规则与解释文字的 JSON）：

- 整段改写为 £48,000，对比在 2025-06-01 拆段（前 £38,000、后 £48,000）：
  - 评估日 2025-06-01、2026-01-15、2027-01-15、2029-01-15、2030-04-03、2030-07-15；
  - 六个日期全部相同。
- 首段 £48,000，对比首段从未改写（£38,000）：
  - 评估日 2027-01-15、2029-01-15、2030-07-15；
  - 全部相同。
- 只有评估日落在首段内时，当前薪资才起作用，这是事件的本意。例如 2025-06-01：
  - £38,000 时 `CL-SW-GOING-RATE` 为 `FAIL`（低于 Table 2 £40,000）；
  - £48,000 时为 `PASS`。

## 4. 发现与建议（范围外，不实现）

1. **游戏提示截止日（Fable / sol 定）**：
   - 2024-04-04 前的群体在现行法下有一个硬截止：按 row C 定居必须在 2030-04-03 前申请，晚了就按 row A。林遥的 £49,920 达不到 Table 1 的 £54,700。
   - 引擎解释里已经写了"且申请日早于 2030-04-04（SW 4.2(b)(ii)）"。游戏是否在定居入口或续签时提醒玩家，由 Fable / sol 决定。
2. **续签也有同一截止**：
   - 按 SW 4.2(a)–(b)，2030-04-04 起的续签也只能用 options A–E。没有 PhD、不在 ISL、不属新入行时，就是 option A：£41,700，加 Table 1 的 going rate。
   - 游戏的 `extend` 不核对。例如林遥若在 2030-04-04 之后以 £49,920 续签，现行法下不满足 option A。
   - 引擎不建模续签；游戏是否体现由 Fable 定。SRC-001 p44 的 2035 延长尚未生效（PD-040）。
3. **2035 落地时只需改一个参数**：
   - SW 24.3 row C 的截止日是引用 SW 4.2(b) 得来的。
   - 如果落实 SRC-001 p44 的 Statement of Changes 改的是 SW 4.2(b)(ii) 的日期，定居 row C 会跟着延后。那时只需按 `docs/versioning.md` 更新参数 `skilledWorkerPre2024ApplicationsBefore`（`current-law-2026-11.ts:158`）。
   - 如果改成另立的、只管续签的条款，定居 row C 仍是 2030-04-04。
   - 12 月那批规则提交时要看清楚。
4. **游戏的年化收入（sol）**：
   - `syncSalary` 把新年薪整额写进当前 tax year。这一年完成后，会进入 Earned Settlement 的 best-years 窗口：窗口只取申请日所在 tax year 之前的完整 tax year（`es-contribution.ts:45`）。
   - 年中加薪若跨过 £50,271 或 £125,141（`earned-settlement-2026-11.ts:46–59`，SRC-001 p15、p46），这一年会被多算。
   - 林遥从 £38,000 到 £48,000、再到 £49,920，没有跨过任何门槛（£12,571 / £50,271 / £125,141），结论不变。
