# 任务 6.5：问卷输入——现金储蓄与伴侣领取特定福利（负责：astra；Fable 验收）

## 背景

6.4（Opus）已合并：现行法律栏的 `CL-FAMILY-FINANCIAL`（Appendix FM 5 年伴侣路线的财务要求）现在会用储蓄补足收入缺口，并接受伴侣领取特定福利的替代。契约见 `docs/contracts.md` §17（字段以它为准）：

- `PersonTimeline.cashSavings?: number`（申请人与伴侣合计的现金储蓄，GBP；缺省 = 未填写；`0` = 无储蓄）
- `PersonTimeline.partnerSpecifiedBenefit?: boolean`（伴侣领取 E-LTRP.3.3(a) 所列福利之一；缺省 = 否）

引擎的判断顺序（§17.3）：收入达标 → PASS；储蓄 ≥ £16,000 + 收入缺口（定居阶段不乘 2.5）→ PASS；伴侣领福利 → UNKNOWN + PD-075；收入或储蓄未填 → UNKNOWN；储蓄不够 → FAIL。在问卷补上这两个输入之前，收入不足的用户只会看到"未填写储蓄"而无处可填，所以本任务尽快做。做法同 5.5（`docs/tasks/5.5-web-current-law-inputs-2.md`、`test/current-law-inputs.test.tsx` 是样板）。

## 必读

## A. 问卷输入

- 显示条件（主流程与主申请人子流程都适用）：该 timeline 有 `FAMILY_PARTNER_OR_PARENT` + `MAIN` 且 `familyPermission === 'PARTNER_FIVE_YEAR'` 的片段。其他情形不显示，也不写入字段。
- 收入步骤：数字输入"现金储蓄（本人与伴侣合计，£）"，提示"收入不足时可用储蓄补足：至少 £16,000 加收入缺口（E-LTRP.3.1(b)；定居申请按 E-ILRP.1.3(1A) 不乘 2.5）；填 0 表示没有储蓄"。空 → `undefined`；非负整数校验在边界做（非法值不写入，给错误提示）。
- 福利步骤：复选框"我的伴侣领取 E-LTRP.3.3(a) 列明的福利（如 Carer's Allowance、Personal Independence Payment、Disability Living Allowance、Attendance Allowance 等）"，勾选 → `true`，不勾 → `undefined`。
- 显示条件不再成立时（路线或许可类型改掉）清空两个字段，沿用现有的清理方式。
- `lib/share.ts`：两个字段的取值校验（非负数、布尔）。
- What-if 不加控件（储蓄在问卷改；`CL-FAMILY-FINANCIAL` 已映射到收入控件）。
