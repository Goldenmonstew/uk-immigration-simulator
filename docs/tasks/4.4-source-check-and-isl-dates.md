# 任务 4.4：来源核对改进与 ISL 移除日期（负责：sol；Fable 验收）

## 背景

3.1 的 `check-sources.mjs` 严格比较整份响应的 sha256，GOV.UK 页面因 CSRF token、CSP nonce、随机 accordion ID 等每次都报 changed（3.1 报告 §4 的诊断：10 个页面提取 `<main>`、去 script / style、归一化空白后正文完全一致）。用户决定：改脚本口径，**并加**每周自动核对的 GitHub Actions（只输出日志）；另把 ISL 的 `removalDate` 规范为 ISO 日期供 4.5 的引擎推导使用。

## 必读

- `AGENTS.md`；`docs/tasks/phase-4-plan.md` §2 的 4.4；`docs/tasks/reports/3.1-isl-and-source-check.md` §2、§4。
- `packages/policy-data/scripts/check-sources.mjs`、`scripts/extract-immigration-salary-list.mjs`、`src/data/immigration-salary-list.ts`、`test/immigration-salary-list.test.ts`；`docs/SOURCES.md`（含 4.1 新增的 SRC-020–023）。

## A. check-sources 口径

- 对 GOV.UK 的 HTML 来源（URL 以 `https://www.gov.uk/` 开头）增加"归一化正文"比较：提取 `<main>`（没有 `<main>` 的页面退回 `<body>`），去掉 `script` / `style` / `noscript`、HTML 注释、所有标签属性，归一化空白后算 sha256，与**本地快照同样处理后的值**比较；结果仍按 ID 打印三类，并在 changed 时说明是"原始 hash 变、正文一致"还是"正文变"。原始 sha256 照旧打印一行作为存档证据。
- SRC-011（legislation.gov.uk `/new`，动态列表）单独标注为 `dynamic`，不计入 changed。
- 保持零依赖（Node 内置 `fetch`、`crypto`，字符串处理用正则即可，不引入 HTML 解析库）；只读，不改任何文件，不进 CI。
- 报告里贴一次完整运行结果：预期除 `dynamic` 外全部 unchanged（含 4.1 的四个新来源）。

## B. 每周自动核对（GitHub Actions）

- `.github/workflows/check-sources.yml`：`schedule` 每周一 06:00 UTC + `workflow_dispatch`；步骤照抄 `ci.yml` 的 checkout / pnpm / Node 设置，然后 `node packages/policy-data/scripts/check-sources.mjs`。脚本在有 changed / failed 时退出码 1 → 该 run 显示失败，这就是全部的提醒机制；不开 issue、不发通知、不影响 CI 与 Deploy 工作流、不加 secrets。`docs/deploy.md` 或 `docs/SOURCES.md` 顶部加两句：在哪里看结果、失败了怎么办（人工核对、按 `docs/versioning.md` §2–§3 登记）。
- 验收时 Fable 用 `gh workflow run check-sources.yml` 手动触发一次并看日志。

## C. ISL `removalDate` 规范为 ISO

- `extract-immigration-salary-list.mjs` 把 "31 December 2026" 这类日期转换为 `2026-12-31`（无法解析的原样保留并在生成文件里加注释说明），重新生成 `src/data/immigration-salary-list.ts`；`ImmigrationSalaryListEntry.removalDate` 的注释改为"ISO 日期"；测试补：所有 `removalDate` 匹配 `^\d{4}-\d{2}-\d{2}$`，并抽查 6135 为 `2028-07-22`。
- 引擎此时不读这个字段（4.5 再用），现有 engine 测试与 fixtures 不得变化。
