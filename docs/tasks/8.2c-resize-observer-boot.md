# 任务 8.2c：画布启动不能只靠 ResizeObserver 的首次回调（负责：astra；Fable 验收）

## 现象（Fable 在 8.2b 构建上实测，内置浏览器）

点"继续上次"后，`observeTownSize` 调用了 `observer.observe(host)`（此时宿主已是 949×655），但 ResizeObserver 的回调在 7 秒内一次都没触发，于是 `createGame` 从未执行，页面只有纯色背景、没有 canvas、没有请求 `town.json`。手动把宿主高度改 1px 再改回，回调立刻触发，游戏随即正常启动并渲染地图——证明逻辑本身没问题，只是启动条件绑在"首次尺寸回调"上，而某些浏览器 / 面板状态下这个首次回调不会按预期送达（之前偶尔能跑起来，是因为面板尺寸刚好变化过）。另：之前控制台里的 `Framebuffer status: Incomplete Attachment` 来自 8.2 的 0 宽度版本，8.2b 后在同一浏览器用 Phaser 3.90（WebGL，949×655）直接建游戏没有错误。

## 要做的

- `apps/web/app/game/town-canvas.tsx` 的 `observeTownSize`：`observer.observe(element)` 之后**立即同步调用一次 `resize()`**（宿主已有尺寸就直接建游戏），并在 `requestAnimationFrame` 再调一次兜底；去掉对 `document.readyState === 'loading'` 的判断（客户端组件挂载时文档已就绪）和 `DOMContentLoaded` 监听。保留 ResizeObserver 用于后续尺寸变化、保留非零尺寸判断与 Canvas 回退。
- 现有 7 项 jsdom 测试相应改为"observe 后立即创建、尺寸为 0 时不创建、之后回调再 resize"。
- 不改其他文件。

## 验收（Fable）

- 构建后浏览器里点"继续上次"或"开始"，1 秒内出现 canvas 并渲染地图，不需要任何尺寸变化；刷新两次都如此；375px 同样。
