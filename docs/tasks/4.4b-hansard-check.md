# 任务 4.4b：Hansard JSON 的来源核对口径（负责：sol；Fable 验收）

## 背景

4.4 之后 `check-sources.mjs` 对 GOV.UK 页面按归一化正文比较，17 个 HTML 来源全部 unchanged；但 SRC-003（Hansard 上议院辩论的 API JSON）仍按原始字节比较，而 Hansard API 的响应里内部 ID 与更新时间会变、发言内容不变，于是每周工作流会一直报 changed（退出 1），失去提醒意义。本任务只定这一类来源的比较口径。

## 必读

- `AGENTS.md`；`packages/policy-data/scripts/check-sources.mjs`（4.4 的归一化函数与分支结构）；`docs/SOURCES.md` SRC-002 / SRC-003 的登记备注；`policy-sources/2026-11-02-hansard-*.json`。
- 4.4 报告 §4（SRC-003 变化的是哪些字段）。

## 要做的

- 对 URL 以 `https://hansard-api.parliament.uk/` 开头且快照为 `.json` 的来源：本地与远端都解析 JSON，只比较"发言内容"——取每条 contribution / item 的文本字段（以快照实际结构为准，例如 `Items[].Value` 或等价字段）按顺序拼接后算 sha256；忽略 ID、时间戳、计数等元数据。正文一致 → unchanged（打印"原始 hash 变、正文一致"或"均一致"），正文变 → changed。解析失败 → failed。
- 原始 sha256 照旧打印一行作存档。SRC-002（下议院）同样走这个口径。
- 零依赖、只读；不改工作流、不改其他来源的口径。
- 报告里贴一次完整运行结果：预期除 SRC-011 dynamic 外全部 unchanged，退出 0。

## 技术约束

- 只改 `packages/policy-data/scripts/check-sources.mjs`；不改其他文件；不 push。
- Opus 在改 `packages/engine`；没有其他 sol 任务在跑。

## 验收（Fable）

- gate 全过；本机跑一次脚本退出 0；临时改动本地快照里一条发言文本后脚本报 changed（验证口径真的看正文）。
