# 任务 6.4：5 年伴侣路线的储蓄与福利替代（负责：Opus；Fable 验收）

## 背景

`CL-FAMILY-FINANCIAL` 现在只按收入判断（E-LTRP.3.1(a)，过渡 E-LTRP.3.7(a) 并按 E-LTRP.3.8 封顶），储蓄（E-LTRP.3.1(b) / E-LTRP.3.7(b)）与伴侣领取特定福利（E-LTRP.3.3）写在假设里"未建模"。家庭路线用户常靠储蓄补收入缺口，现在一律按收入判 FAIL。本任务补这两项。Earned Settlement 栏不动。

契约先行：第一个 commit 只改 `docs/contracts.md`（新增 §17）与 `docs/pending-details.md`（新 PD），commit 后停下等 Fable 评审；收到"继续"后再写参数、规则、fixture、测试。先 `git merge main`（main 已合并 6.2 并含本任务书）。

## 必读

- `AGENTS.md`；`docs/contracts.md` §12（家庭伴侣 5 年路线）、§16（`decidedBy`，本任务不改）；`packages/engine/src/rules/current-law.ts` 的 `familyIncomeThreshold`、`clFamilyFinancial`、`onFamilyPartnerFiveYear`；`packages/policy-data/src/parameters/current-law-2026-11.ts` 的 `familyPartner*` 参数；`packages/policy-data/fixtures/cl-family-partner-five-years.ts`；`docs/SOURCES.md` SRC-024 常用定位的"财务"各条；`packages/engine/test/random.test.ts`（必须继续通过）。
- SRC-024 快照原文要点（Fable 预读，段号以快照为准）：
  - E-LTRP.3.1：(a) 指定年毛收入至少 £29,000；**或** (b) 指定储蓄 (i) £16,000 **加** (ii) 相当于 2.5 倍收入缺口（E-LTRP.3.2(a)–(f) 来源的年毛收入与 3.1(a) 要求之差）的额外储蓄；**或** (c) 满足 E-LTRP.3.3（除非 EX.1 适用）。
  - E-LTRP.3.7（过渡）：(a) £18,600 + 首名子女 £3,800 + 其后每名 £2,400，"alone or in combination with" (b) 储蓄 (i) £16,000 加 (ii) 2.5 倍缺口；或 (c) E-LTRP.3.3；E-LTRP.3.8 超过 £29,000 时只需 £29,000。
  - E-ILRP.1.3(1A)：定居申请须满足 Section E-LTRP，且适用 E-LTRP.3.1(b)(ii) / E-LTRP.3.7(b)(ii) 时**去掉 "2.5 times"**——即定居阶段储蓄 ≥ £16,000 + 收入缺口即可。
  - E-LTRP.3.3：(a) 申请人的伴侣领取下列之一：Disability Living Allowance、Severe Disablement Allowance、Industrial Injuries Disablement Benefit、Attendance Allowance、Carer's Allowance、Personal Independence Payment、Armed Forces Independence Payment / Guaranteed Income Payment、Constant Attendance Allowance / Mobility Supplement / War Disablement Pension、Police Injury Pension、Child Disability Payment (Scotland)、Adult Disability Payment (Scotland) 等（以快照为准）；(b) 申请人须证明 adequate maintenance and accommodation，不依赖 public funds（E-LTRP.3.4 住宿）。
  - E-LTRP.3.2：可计入的收入 / 储蓄来源清单（本任务不校验来源种类，写假设）。

## 要做的

### A. 契约 §17（第一个 commit）

- 字段（放在 `PersonTimeline` 上，与片段无关）：`cashSavings?: number`（申请人与伴侣合计的指定储蓄，GBP；缺省 = 未填写）；`partnerSpecifiedBenefit?: boolean`（伴侣领取 E-LTRP.3.3(a) 列明的福利之一；缺省 = 否）。不加别的字段。Appendix FM-SE 的持有期与证据规则、E-LTRP.3.2 的来源种类只写假设。
- `CL-FAMILY-FINANCIAL` 的判断顺序（只对 5 年伴侣路线主申请人；其他情形不变）：
  1. `partnerSpecifiedBenefit` 为真 → 走 E-LTRP.3.1(c) / 3.7(c)：须满足 3.3(b) adequate maintenance and accommodation，没有数字门槛 → `UNKNOWN` + 新 PD（建议 PD-075：adequate maintenance 的口径——Appendix FM-SE 与指引里的 income support 比较法未登记），解释写明福利清单由用户自报、按 3.3(a) 处理。
  2. 否则按现有逻辑：收入（本人 + 伴侣）≥ 门槛 → `PASS`，不看储蓄。
  3. 收入不足：缺口 = 门槛 − 收入。`cashSavings` 缺省 → `UNKNOWN`（解释：储蓄至少 £16,000 + 缺口可满足，未填写储蓄）；已填 → `cashSavings` ≥ `familyPartnerSavingsBase`（£16,000）+ 缺口 → `PASS`（解释引 E-LTRP.3.1(b) / 3.7(b) 与 E-ILRP.1.3(1A) 去掉 2.5 倍）；否则 `FAIL`（解释给出还差的金额）。
  4. 收入未填（现有 `UNKNOWN`）：解释补一句"储蓄可替代收入缺口"。
- 哪些 `UNKNOWN` 带 PD：只有 3.3 的那条带 PD-075（其他都通过时 → `POTENTIALLY_ELIGIBLE`）；收入未填、储蓄未填属用户可补的输入，不带 PD（→ `INSUFFICIENT_INFORMATION`）。
- 参数：`familyPartnerSavingsBase`（16000）进 `current-law-2026-11.ts`，来源 E-LTRP.3.1(b)(i)、E-LTRP.3.7(b)(i)；去掉倍数的依据 E-ILRP.1.3(1A) 写在规则 `sources`，不设参数。
- 不做：E-LTRP.3.2 的来源校验、FM-SE、EX.1、10 年路线（SETF 无财务要求）、Earned Settlement 栏、问卷（6.5 由 astra 做）。
- 现有 fixture 的 `expected` 不改；如有现有测试断言"收入不足 → FAIL"，按新语义改为储蓄缺省 → `UNKNOWN` 并在契约里列出；`bilingual` 快照只变解释与来源。
