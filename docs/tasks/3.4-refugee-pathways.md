# 任务 3.4：难民路径（负责：Opus；Fable 验收）

## 目标

让三条保护类路线（`SAFE_AND_LEGAL`、`CORE_PROTECTION`、`PROTECTION_WORK_AND_STUDY`）在 Earned Settlement 栏得到真实结论，不再短路为"需要受监管建议"。依据 SRC-001 Chapter 7（物理页 p36–p40，案例 p40）与 Table 2（p47–p48）。现行法律栏不变：`CL-SCOPE` 仍只建模 Skilled Worker 与 Long Residence（难民许可按现行 LR 11.1 计入 10 年连续合法居留，已有逻辑）。

## 工作方式

1. **第一个 commit 只做契约**：`packages/engine/src/types.ts` 的新增字段 + `docs/contracts.md` 新增 §11 "难民路径" + 参数名（可先写进 contracts，不必同时改参数文件）。提交后**结束本轮回复**，在回复里列出契约改动与下面"设计说明"里你的取舍；Fable 评审后用消息告诉你"继续"或要改什么。评审通过前不要写规则。
2. 契约评审通过后 Fable 会把这个契约 commit **单独合到 main**，astra 的 3.5（问卷与结果页）按它开工。因此之后**不要再改字段名与取值**（可以加字段、加注释）。
3. 之后一条规则一个 commit，带 positive / negative / boundary 测试，每步 gate 全过后自己 commit（`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`），不 push。
4. 并行约束：astra 之后在改 `apps/web/**`（不要碰）；sol 没有在跑。你在 policy-data 里可改 `src/parameters/earned-settlement-2026-11.ts`、`src/data/display-names.ts`（如需新显示名）、`fixtures/**`；`docs/` 里可改 `contracts.md`、`pending-details.md`、`SOURCES.md`（只加 SRC-001 的"常用定位"）。

## 设计说明（契约回合里请逐条表态）

1. **推出前时间的处理**：Core Protection / PWS 尚未推出（PD-034），推出前已有的难民身份时间是否计入未定（PD-029、PD-043）。建议 `ES-PROTECTION-PATHWAY` **按用户填写的片段起止日计算、状态照常 PASS**，在 `assumptions` 里声明这一点并在 `pendingDetails` 列出 PD-029 / PD-034 / PD-043；不要因此输出 UNKNOWN，否则 p40 四个官方案例无法复现、所有难民永远只能得到 POTENTIALLY_ELIGIBLE。
2. **Article 31**：非法入境 + 用户声称受保护 → 年限规则 UNKNOWN（PD-032）；聚合层会得到 POTENTIALLY_ELIGIBLE 或按基础年限投影——请说明投影用基础年限还是 +10。
3. **Legacy UKRS 推导**：是否同意由片段起始日推导（而不是要求用户另选 `LEGACY_SAFE_AND_LEGAL`）。
4. **contribution 计数**：PWS 期间内的完整 tax year 怎么取（起点所在 tax year 是否算）。
5. **ES-BREACH 与非法入境的分工**（见上表）。
