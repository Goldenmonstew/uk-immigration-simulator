# 任务 11.1：人物与剧情（负责：sol；Fable 验收）

## 背景

Fable 线上试玩了三局（见 `docs/tasks/phase-10.5-plan.md` 背景）。人物上的主要问题有三个：
- **台词同腔**：9 个人说的都是同一种散文式小感慨。去掉名字认不出是谁，也不回应玩家近况。比如两年后周沅还在说"冰箱左边那格还空着"。
- **好感剧情模板化**：60 段几乎都是"对方遇到小麻烦，你帮把手，结尾留个空位"。两段选项只差一个小动作。
- **好感太慢**：随意玩家一局只解锁约 20 段好感剧情。

用户决定做人物与剧情。本任务只改 `packages/game`。计划见 `docs/tasks/phase-11-plan.md`。

## 必读

- `AGENTS.md`、`docs/tasks/phase-11-plan.md`、`packages/game/src/style-guide.md`。
- `packages/game/src/npcs.ts`、`town-dialogue.ts`、`family.ts`、`balance.ts`、`game.ts` 的 `talk()`。
- `packages/game/test/**`。

## A. 人物声音表（先做，写进风格指南）

- 在 `style-guide.md` 加一节"人物声音"。范围：8 位常驻镇民、周沅，以及三个角色的全部家人。
- 每人写清：
  - 说话习惯，即句式、口头语、长短；
  - 常聊的话题，以及从不聊的话题；
  - 怎么开玩笑，也可以不开；
  - 和玩家熟起来以后说话怎么变；
  - 3 句示范。
- **人人要不同**：
  - 至少有人话少直接，有人爱打比方；
  - 有人爱抱怨天气，有人只谈工作；
  - 戴夫这类酒吧老板要能接梗。
- 同步改风格指南里限制太死的条目：
  - 好感剧情允许 3–6 段，每段 ≤ 50 字，合计 120–260 字；
  - 台词仍 ≤ 40 字。

## B. 台词重写

1. **按声音表改写**：全部镇民、周沅和家人的台词。
   - 弱的"日常小感慨"可以删。
   - 每人至少保留 70 句，家人与周沅至少 45 句。
2. **回应情境**：至少 30% 的台词挂情境条件，包括季节、天气、时段、节日、好感档位和玩家近况。
   - 每人至少 8 句"回应玩家近况"，挂对应旗标或条件。
   - 近况包括：刚续签、升职或加薪、换工作、考过英语或 Life in the UK、出国刚回来、钱紧、心情很差、好感刚升一档。
   - 需要的旗标若不存在，可以在 `game.ts` 里补上设置点，不改公开 API。
3. **只适合某个阶段的台词挂条件**：比如"刚认识""刚合租"只在第一年；"我们认识好久了"要求好感 ≥ 6 心或第 4 年以后。
4. **盲测自检**：每人随机抽 5 句，去掉名字，自己判断能否认出说话人，把结果写进报告。Fable 验收时会让独立子代理盲猜，目标命中率 ≥ 70%。

## C. 好感剧情重写（12 人 × 2 / 4 / 6 / 8 / 10 心，共 60 段）

1. **每人一条弧线**：
   - 2 心：认识这个人的日常。
   - 4–6 心：揭示一段背景，比如为什么来小镇、在担心什么。
   - 8 心：一次困难或分歧，玩家的选择有分量。
   - 10 心：改变或和解，留下一个以后还在的小习惯。
   - 弧线要和此人在移民主题里的位置呼应，比如阿德也在等续签、莉娜被拒签、拉赫曼早已入籍。但不写规则数字，不预测获批。
2. **去模板**：
   - 每人 5 段里，"递物 / 扶住 / 帮忙拿"式动作最多 1 段；
   - 结尾"留空位 / 留一格"全局最多 3 段；
   - 至少一半场景有对白来回，不是只有动作描写。
3. **选项要有差别**：
   - 至少一半的剧情，两个选项设不同旗标，影响后面的台词或下一段剧情的一句话；
   - 选项可以有轻微代价，比如心情 -2 换好感 +更多。
4. 场景里的时间、地点、天气要与触发条件一致，沿用现有的条件机制。

## D. 好感速度

- 在 `balance.test.ts` 加一个"随意"策略：
  - 每天逛 4–6 处；
  - 只和碰到的人聊；
  - 偶尔送礼；
  - 遇事件随机选。
- **目标**：
  - 随意策略三角色 20 种子，平均每局好感剧情 ≥ 32 段；
  - 积极策略不超过 55 段；
  - 写成断言。
- 只调 `balance.ts` 的游戏设定，比如聊天、送礼的好感值，或季末衰减。不改规则相关的数字。

## E. 体量与回归

- 三角色积极策略：每局不重复汉字 ≥ 15,000，台词不重复率 ≥ 80%，不降阈值。
- 报告给出修改前后的数字，按台词 / 事件卡 / 好感剧情 / 公告分列；同时给出随意策略的好感剧情数。
- 每个"20 seeds"测试本机 ≤ 45 秒；新的随意策略测试如果超过，给它单独时限。CI 慢约 3 倍。

## 技术约束

- **范围**：只改 `packages/game/**` 与报告。
  - 不改 engine、policy-data、apps/web、`docs/SOURCES.md`、`PROGRESS.md`、`AGENTS.md`、`CLAUDE.md`。
  - 不加依赖，不 push。
- **公开 API**：名字与形状不变，不加新导出。
  - 客户端靠台词 / 剧情 id 和 `heart` 字段工作。剧情 id 的格式 `heart-<npc>-<level>` 不变。
- **文案**：
  - 人物虚构；
  - 笑点落在处境，不拿身份取笑；
  - 不说教；
  - 不写政策数字；
  - 中英文同步，英文像说话。
- **不过度工程化**：不加配置项、抽象层、防御分支。
- **验收命令**：`pnpm lint && pnpm typecheck && pnpm test && pnpm build`（全仓），commit 前全部通过。
- **视觉**：Codex 环境里没有浏览器，视觉验收由 Fable 做。
- **Git**：Codex 的沙箱不能写 `.git`。不要尝试 commit。把改动按"应当成为的 commit"分组写进报告，每组写 commit message 与文件清单。
