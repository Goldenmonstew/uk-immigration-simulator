## A. 签证与评估（W1、W2、W15，一个 commit）

1. **W1 恢复签证提醒**：
   - 每季第一天的早晨，满足下面两个条件时，在早晨卡里提醒，并给"去签证中心"按钮：
     - 当前许可剩余 ≤ 6 个月；
     - 没有相接的续签。
   - 复用 `needsVisaReminder` 与现有文案 `game.visaReminderTitle` / `game.visaReminder` / `game.visaVisit`，阈值改成 6。
   - "快进这一季"的确认框也要提醒，条件是当前许可会在本季结束前到期、且没有相接的续签：说明快进会直接过完这一季。
2. **W2 续签后的顶栏**：
   - 有相接的续签时，顶栏显示到连续许可最后一天的剩余月数，或"已续签至 YYYY-MM"，并停止闪烁。
   - 没有续签时保持现状：≤ 6 个月闪烁。
3. **W15 顶栏两栏评估**：
   - 结果没有 `earliestDate` 时，不显示"0%"和进度条长度，改成"—"。
   - `INSUFFICIENT_INFORMATION` 时，在结论下面用一行列出"还差："，内容是结果里 UNKNOWN 规则的标题，例如"还差：通过 Life in the UK 考试"。不再只显示"信息不足，暂无法判断"。
   - 市政厅的完整两栏不改。
4. **测试**：
   - 提醒在 ≤ 6 个月、无续签时出现，续签后不出现；
   - 快进确认框在到期季出现警示；
   - 续签后顶栏月数变长、不闪；
   - 无 `earliestDate` 时显示"—"，`INSUFFICIENT_INFORMATION` 时列出 UNKNOWN 标题。

## B. 小镇里的走动与菜单（W3–W7，一个 commit，可按需拆两个）

1. **W3 节日站位**：
   - 同一户外锚点上的多个人，围绕锚点分散到相邻的可走格子，参考室内的 `homeSpot`，每人一格。节日时 9 个人都能在地图上分别点到。
   - 节日当天村绿地菜单的"在这里的人"，列出在节日摊位（`green-stall`）的人，点了能聊天。`talk` 本来不查位置。
2. **W4 不顺路进店**：寻路中途经过别家门口不自动进入。只有走到终点、且终点就是那扇门时才进入。
3. **W5 门口再点**：已经站在某地点门口时，再点地点列表里的同名按钮，直接打开那个地点。
4. **W6 聊完回菜单**：从地点菜单（包括家里的书桌菜单）点人聊天，"待会儿见"后回到原来的菜单，而不是回到小镇。
5. **W7 开关门与"来不及"**：
   - 地点列表里，当前关门的地点按钮变灰，并标"关门"。可以点，点了走过去仍显示营业时间。
   - 判断用 `places` 的营业时间。`LocationMenu` 里已有同样的判断，抽成一个共用函数，不要复制。
   - 地点开着、菜单里却没有可做的行动时，显示一句原因：
     - 因为离关门太近，就说"来不及在 HH:MM 关门前做完"。一种简单做法：拿开门时刻的状态调用 `activities()`，和现在的比较。
     - 其他情况说"此刻没有可用行动"。
     - 签证中心说"眼下没有要办的手续，到可以续签时这里会出现「续签」"。
6. **测试**：
   - 同锚点的人位置各不相同；
   - 节日村绿地菜单列出在场的人；
   - 路过门口不进店；
   - 站在门口点按钮直接进入；
   - 聊完回到原菜单；
   - 关门地点按钮带"关门"；
   - 无行动时的原因文字。

## C. 小修正（W8–W12，一个 commit）

1. **W8**：村绿地只在 `shop()` 有商品时才显示商店，非节日不显示"数量"框。
2. **W9**：
   - 生长显示用该作物实际所需的天数（`items` 里的 `grows.days`），不写死 4；
   - 厨房时长用 `game.minutes`，不显示"min"。
3. **W10**：快进途中不弹早晨卡；快进停下时，直接显示停下的原因，即事件、季末小结或提醒。
4. **W11**：带 `ending` 效果的行动（申请定居、离开英国），点击后先弹确认框，写明"这会结束这一局"，确认后才执行。复用现有的确认框样式。
5. **W12**：
   - 事件卡的选项按钮里只保留效果标签，不再整句显示 `note`。
   - 本卡各选项的 `note` 去重后，放到卡片底部一行小字。
   - 风格指南要求机制说明只放在 note，因此不能删掉不显示。
6. **测试**：
   - 非节日村绿地没有数量框；
   - 生长分母等于作物天数；
   - 厨房没有"min"；
   - 快进时不出现早晨卡；
   - 结束本局的行动先确认；
   - note 不在按钮里，且只出现一次。

## 技术约束

- **范围**：只改 `apps/web/**` 与报告。
  - 不改 `packages/**`、`docs/SOURCES.md`、`PROGRESS.md`、`AGENTS.md`、`CLAUDE.md`。
  - 不 push。
- **公开 API**：只用 `packages/game` 现有导出。真需要新导出时，停下来在报告里写清原因，不要自己加。
- **不过度工程化**：不加依赖、状态库、配置项。能放进现有组件就不新建文件。
- **文案**：中英两套同时改，新文案遵守 `packages/game/src/style-guide.md` 的语气；不写政策数字。
- **验收命令**：`pnpm lint && pnpm typecheck && pnpm test && pnpm build`（全仓），commit 前全部通过。
- **并行**：sol 同时在改季节。若合并后有客户端测试因季号变化失败，由 Fable 处理。你这边以现有 main 的行为为准。
- **视觉**：Codex 环境里没有浏览器。所有布局、地图、图标的视觉验收由 Fable 在浏览器里做；报告里列出需要 Fable 重点看的画面。
- **Git**：Codex 的沙箱不能写 `.git`。不要尝试 commit。把改动按"应当成为的 commit"分组写进报告，每组写 commit message 与文件清单。
