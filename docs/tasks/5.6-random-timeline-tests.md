# 任务 5.6：引擎健壮性——随机时间线测试（负责：sol 写测试；Opus 修复；Fable 验收）

## 目标

证明 `evaluate` 对任意合法输入都不抛错、输出满足不变量；发现的问题只报告，不改规则语义。零新依赖（自写简单随机生成器）。不过度工程化：一个测试文件、一个生成器，固定种子，够用就行。

## 必读

- `AGENTS.md`（sol 不改 `packages/engine/src/**` 的规则语义；本任务只加测试文件）；`docs/contracts.md` §2（六态）、§7、§11–§14（字段与取值）；`packages/engine/src/types.ts`（`SimulationRequest` / `PersonTimeline` / `ImmigrationEpisode` 的全部字段与枚举）、`packages/policy-data/src/routes.ts`（`Route` 列表）、`packages/policy-data/src/data/display-names.ts`（枚举取值）、`packages/engine/test/helpers.ts`、`packages/engine/test/versioning.test.ts`（现有测试风格）。

## 要做的

- `packages/engine/test/random.test.ts`：
  - 自写确定性伪随机数（如 mulberry32，固定种子），生成 `SimulationRequest`：出生日期（1950–2010）、国籍（几个代码）、0–4 段 episodes（路线从全部 `Route` 随机取，`role` MAIN / DEPENDANT，日期有序或故意重叠 / 有空隙，SOC、薪资、ISL、dependantOf、resettlementScheme、sustainedActivity、globalTalentEndorsement / Criteria、familyPermission、innovatorSettlementCriteria、privateLifeRoute 按路线随机填或缺省）、0–3 段 absences、0–7 个 incomeYears（含 partnerEarnings）、benefits、relationships、criminalRecord、immigrationBreaches（含 article31）、english / lifeInTheUk / earningsExemptHealth / governmentDebt / settled / asylumSupportRepayment / protectionStatusRevoked 随机有无；`simulationDate` 在 2026–2040；30% 的用例带 `principal`（另一条随机时间线）；locale 随机 zh-CN / en。
  - 跑 ≥ 2000 个用例，对每个断言：不抛错；`byRuleSet` 的键 = 请求的 `ruleSetIds`（缺省为全部）；每栏 `outcome` 属六态；`LIKELY_ELIGIBLE` 时 `earliestDate === simulationDate`；`LIKELY_NOT_ELIGIBLE` 且有 `earliestDate` 时 `earliestDate > simulationDate` 且 `pathwayYears` 有值；`pathwayYears` 若有值属 {3, 5, 10, 20, 30}；`rules[]` 的 `id` 不重复、`status` 属三态、`explanation` 非空字符串、`sources` 每项有 `srcId` 与 `locator`；`assumptions` 为字符串数组；zh-CN 与 en 对同一请求输出的规则 ID 序列、状态、结论、年限、日期完全一致（只有文字不同）；短路时两栏（或改革栏）没有 `pathwayYears` / `earliestDate`。
  - 某个断言失败时，把该用例的种子与请求 JSON 打印出来（`JSON.stringify`），方便复现。
- 发现的问题写进报告 §4（每条：种子、最小请求、期望 vs 实际），**不要改引擎源码**；由 Opus 另行修复。若某条不变量本身与契约不符（比如某种合法情形下 `pathwayYears` 可以是别的值），在报告里说明并在测试里按契约调整，不要为了让测试过而放宽到无意义。
