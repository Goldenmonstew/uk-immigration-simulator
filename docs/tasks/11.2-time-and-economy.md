# 任务 11.2：时间与经济（负责：sol；Fable 验收）

## 背景

试玩里，快进一年只有 2–3 张事件卡。到后期存款数万英镑没地方花，心情、健康长期顶在 90 以上。事件卡旁白里"你"和"林遥"混用。

Opus 的 10.5c 报告（`docs/tasks/reports/10.5c-going-rate-check.md` §4）指出：林遥按 SW 24.3 row C 申请定居，必须在 2030-04-04 前提交（SRC-004 SW 4.2(b)(ii)），游戏却完全没提。

本任务在 11.1 合并后进行，只改 `packages/game`。计划见 `docs/tasks/phase-11-plan.md`。

## 必读

- `AGENTS.md`、`docs/tasks/phase-11-plan.md`（含政策扫描）、`packages/game/src/style-guide.md`。
- `docs/SOURCES.md`。只有这里登记过的来源可以出现在政策相关文字里。
- `packages/game/src/**`、`packages/game/test/**`。

## A. 事件密度

1. 快进策略（`balance.test.ts` 的 fast-forward）三角色 20 种子平均每年事件卡 ≥ 6 张，不含好感剧情。
2. 做法自选。比如：
   - 每季保底送达的信或早晨卡；
   - 快进的默认作息里顺路和碰到的一位镇民聊天；
   - 补新卡。
3. 但积极策略的体验不能变差：不重复字数和台词不重复率照旧达标，单局事件卡不超过修改前的 1.5 倍。

## B. 政策新闻卡与截止提醒

1. **政策新闻卡**：以小镇视角写一组新闻卡，比如公告栏的剪报、广播、镇民议论。
   - 按真实日期出现，只写 `docs/SOURCES.md` 已登记的事件：
     - 白皮书（SRC-012，2025-05-12）；
     - 咨询发布（SRC-013）；
     - 咨询回应（SRC-001 / SRC-002，2026-11-02）；
     - 其他已入库来源自行判断。
   - 卡在相应日期之后的季度里出现。
   - 每张写一件事和镇上的反应，不写数字，不预测结果，不说教。
   - 在代码注释里写来源 SRC 与定位。
2. **林遥的截止提醒**：只针对林遥，在 2030-04-04 前的一到两季出现。
   - 一张信件或同事闲谈卡，提醒"老规则下的申请窗口"快到期，可以去市政厅看定居还差什么。
   - 截止日期必须引用 SRC-004 SW 4.2(b)(ii)，写进代码注释。
   - 卡面文字可以写日期，但不写薪资数字。
3. **测试**：
   - 新闻卡不早于对应日期出现；
   - 林遥在截止前能收到提醒，截止后不再出现；
   - 其他角色收不到。

## C. 经济与属性起伏

1. **花钱的去处**：至少三类，有持续效果，走现有菜单与小店，不需要新界面。例如：
   - 换房，包括押金和每季房租变化，换来心情或健康的持续加成；
   - 家具或家居小物，一次性购买、永久小加成，数量有上限；
   - 兴趣班或俱乐部，按季收费，提升某项属性或好感。
   - 涉及出国的旅行已有，不要新增会写入离境记录的花钱方式。
2. **目标**（积极策略，三角色 20 种子）：
   - 第 10 年存款中位数比修改前下降至少 40%；
   - 负债或破产相关结局与事件不比修改前多；
   - 第 5 年与第 10 年心情、健康的中位数都在 55–85 之间。
   - 调整写在 `balance.ts`，都是游戏设定，不冒充政策数字。
3. 报告列出修改前后的这些数字。

## D. 叙述人称统一为"你"

- 事件卡标题、正文、选项、结果文字里的旁白，凡是指玩家角色的，一律写"你"，不写"林遥 / 陈嘉宁 / 嘉宁 / 索菲娅"。
- 对白引号里别人叫名字的情况可以保留。
- 风格指南同步写上这条。
- **测试**：所有事件文本去掉引号内的对白后，不含三位角色的名字。

## E. 体量与回归

- 积极策略：三角色每局不重复汉字 ≥ 15,000，台词不重复率 ≥ 80%，11.1 新增的随意策略断言仍过。
- 报告写修改前后各项数字，以及每个"20 seeds"测试的本机耗时，单个 ≤ 45 秒。

## 技术约束

- **范围**：只改 `packages/game/**` 与报告。
  - 不改 engine、policy-data、apps/web、`docs/SOURCES.md`、`PROGRESS.md`、`AGENTS.md`、`CLAUDE.md`。
  - 不加依赖，不 push。
- **公开 API**：名字与形状不变，不加新导出。新行动、新物品要能被现有界面显示。若确实需要界面配合，在报告里写清，由 Fable 另开 astra 任务。
- **政策**：政策数字与日期只用已入库来源，并在代码注释里写 SRC 与定位；不预测获批。
- **不过度工程化**：不加配置项、抽象层、防御分支。
- **验收命令**：`pnpm lint && pnpm typecheck && pnpm test && pnpm build`（全仓），commit 前全部通过。
- **视觉**：Codex 环境里没有浏览器，视觉验收由 Fable 做。
- **Git**：Codex 的沙箱不能写 `.git`。不要尝试 commit。把改动按"应当成为的 commit"分组写进报告，每组写 commit message 与文件清单。
