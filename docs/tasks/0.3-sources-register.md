# 任务 0.3：来源登记（负责：Opus）

## 目标

把 `docs/SOURCES.md` 里所有 `todo` / `verify` 项登记完整：官方 URL、发布或版本日期、本地快照、sha256；把研究报告的 30 个引用 ID 映射为确定的 `SRC-xxx p<N>`。全部是文档与快照工作，不写代码。

## 背景

- 产品：UK Immigration Simulator。每条规则必须溯源到官方文件段落，来源登记表是规则引擎的前置依赖。
- 先读 `AGENTS.md`、`docs/00-project-analysis-and-plan.md` §3–§4、`docs/SOURCES.md`。
- 已归档：SRC-001（官方回应 CP 1707 PDF）在 `policy-sources/`。本机有 `pdftotext`，可用 `pdftotext -layout <pdf> <txt>` 抽文本（换页符分页，封面为 p1）；或用 Read 工具按页读。
- 研究报告：`docs/research/2026-11-03-deep-research-report.md`，引用 ID 形如 `turn377160view1`；`SOURCES.md` 末尾有按上下文推断的映射，需要逐条确认。

## 要做的

1. 对 SRC-002 … SRC-013 每一条：
   - 找到官方 URL（gov.uk、hansard.parliament.uk、legislation.gov.uk 优先；律所页面不能作一级来源）。
   - 记录发布日期；Immigration Rules 各 Appendix 记录页面"最近更新"日期和适用的 Statement of Changes 编号。
   - 抓快照到 `policy-sources/`，文件名 `YYYY-MM-DD-<slug>.<ext>`（HTML 存 `.html`，PDF 存 `.pdf`），计算 sha256 填表，抓取日期填今天。
   - SRC-002 / SRC-003（Hansard，2026-11-02 下议院与上议院关于 Earned Settlement 的陈述）：定位陈述中关于实施时间表的句子，在表格备注用自己的话概括，并给出段落或时间戳定位；不要大段复制原文。
   - SRC-007（HC 1691，二手来源称 2027-03-26 起 settlement 需 B2 英语）：核实是否属实。属实则登记 Statement of Changes 的 URL、生效条款编号与日期；不属实则标"未证实"并写明查到了什么。
   - SRC-004（Appendix Skilled Worker）：确认 £41,700 一般门槛与 going rate 要求所在的段落号（`SW x.x` 形式）。
2. 报告引用 ID 映射表：把 30 个 ID 的"推断来源"逐条确认，改成确定的 `SRC-xxx p<N>` 或段落号；确认不了的标"无法确认"并说明原因。
3. 新发现的、MVP-0 需要的官方来源可追加 SRC-014 起（例如 Appendix Continuous Residence、Appendix English Language、Appendix KOL UK），但不要为求全面扩张到 MVP-0 不需要的路线。
4. 单个快照超过 5 MB 的，不要提交，写进报告由 Fable 决定。

## 不要做

- 不改规则语义、不写代码、不改 `docs/00-project-analysis-and-plan.md` 正文（发现其中错误，写进报告）。
- 不改 `docs/pending-details.md`（另一个会话在并行写）。
- 不编造 URL 或页码：每个 URL 必须实际打开过，每个页码必须在快照里核对过。
- 不 push。

## 验收（Fable 会做）

- 抽 5 条以上 SRC 与原文核对 URL、日期、页码。
- 每个本地快照的 sha256 与表中一致。
- 引用 ID 映射表无"推断"字样残留。

## 提交

每完成一组来源一个 commit（例如 `Docs: 登记 SRC-002/003 Hansard 陈述`）。格式见 `AGENTS.md`。最终报告写入 `docs/tasks/reports/0.3-sources-register.md` 并提交。
